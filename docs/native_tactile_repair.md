# Native tactile regeneration from recorded states

The old PickLift readouts were generated by replaying controls with a different
trajectory from the recorded RGB. Their active sensor anchors differ from raw
state FK by up to 11.6 cm. This version regenerates continuous tactile signals
at every recorded full state before constructing policy observations.

`scripts/repair_raw_readouts.py` uses the frozen MuJoCo 3.4.0 assets, native
`tactile_sim.models`, dense surface geometry and 44 readout weights. The output
keeps the original `state22`, `episode_index` and `frame_index` exactly, and
replaces `force44`, `contact44` and `anchors_world`. The sensor order is 32
fingertip taxels followed by 12 FSRs. Object pose is used only to synthesize the
simulated sensor; the policy receives 22 robot coordinates.

The native input adapter has two explicit corrections:

- The object adapter expects XYZW, so MuJoCo WXYZ is reordered; hand quaternions
  retain WXYZ. Actual transformed mesh vertices are checked against MuJoCo FK.
- `mj_differentiatePos` converts consecutive full qpos29 values to qvel28 using
  the original CSV timestamp difference. Episode starts use zero velocity.
  `mj_objectVelocity` returns body COM velocity; it is shifted to the body
  `xpos` origin using `omega × (xpos − xipos)`. Every body's resulting linear
  and angular velocity is checked against the `xpos` Jacobian multiplied by
  qvel. There is no future frame and no `mj_step` in reconstruction.

The original native force law is deliberately retained, including its legacy
`cross(r, omega)` convention. Values are continuous simulator proxies, **not
calibrated forces in Newtons**. Geometry and timing consistency do not establish
physical accuracy of this inherited force model. Correcting its force law would
require a separate data version.

Render comparison also found raw `RGB[t]` matches recorded `qpos[t−1]`, not
`qpos[t]`. The repaired full readout file remains indexed by qpos. Cache assembly
must pair existing VGGT visual points from RGB row `t` with robot state,
repaired tactile and source action from row `t−1`, within the same episode.
The source action is already the historical next-step command, so no additional
action shift is applied. First episode observations are discarded. Cache
metadata records both observation state indices and RGB source indices.

## Reproduce on rimlab-server

Run from `/home/wukf/projects/tactile_enhance_vggt`. The native tactile environment
is separate from the new training environment because it provides the frozen
MuJoCo/Kaolin dependencies. Historical source directories are read only; outputs
are written under the new project's `artifacts` directory.

```bash
NATIVE_PY=/home/wukf/miniforge3/envs/te/bin/python
DYNAMIC_ROOT=/home/wukf/projects/tactile_enhance/rgbs_dynamic44_20260921
RAW_ROOT=/home/wukf/projects/tactile_enhance/rgbs_corrected44_20260906/raw_numeric/Mujoco_Picklift_random_cube_260212
TIMESTAMPS_ROOT=inputs/raw_timestamps
SOURCE_READOUTS=$DYNAMIC_ROOT/readouts/picklift.npz
COMMON=(--dynamic-root "$DYNAMIC_ROOT" --raw-root "$RAW_ROOT"
  --timestamps-root "$TIMESTAMPS_ROOT" --source-readouts "$SOURCE_READOUTS")

# Probe 100 frames spread across the original episodes.
CUDA_VISIBLE_DEVICES=1 "$NATIVE_PY" scripts/repair_raw_readouts.py "${COMMON[@]}" \
  --max-frames 100 --output artifacts/repair_probe/raw_native_velocity_fixed_probe100.npz

# Independent episode shards, one per GPU; run these concurrently.
CUDA_VISIBLE_DEVICES=1 "$NATIVE_PY" scripts/repair_raw_readouts.py "${COMMON[@]}" \
  --max-frames 0 --num-shards 2 --shard-index 0 \
  --output artifacts/raw_native/picklift_shard00.npz > artifacts/raw_native/shard00.log 2>&1 &
CUDA_VISIBLE_DEVICES=2 "$NATIVE_PY" scripts/repair_raw_readouts.py "${COMMON[@]}" \
  --max-frames 0 --num-shards 2 --shard-index 1 \
  --output artifacts/raw_native/picklift_shard01.npz > artifacts/raw_native/shard01.log 2>&1 &
wait

"$NATIVE_PY" scripts/repair_raw_readouts.py "${COMMON[@]}" \
  --merge-inputs artifacts/raw_native/picklift_shard00.npz artifacts/raw_native/picklift_shard01.npz \
  --output artifacts/raw_native/picklift_raw_native.npz

# Hash all original qpos29 NPY files, including the privileged object pose.
"$NATIVE_PY" scripts/hash_raw_inputs.py \
  --raw-root "$RAW_ROOT" --timestamps-root "$TIMESTAMPS_ROOT" \
  --source-readouts "$SOURCE_READOUTS" \
  --output artifacts/raw_native/raw_input_profile.json \
  --attach-report artifacts/raw_native/picklift_raw_native.report.json \
  --rgb-timing-audit docs/raw_rgb_timing_audit.json
```

The merge requires exact full coverage of the source states and verifies shard
checksums. Only the merged report has `complete: true`; it binds the final NPZ
SHA256, frozen native model/geometry/mesh, timestamps and raw input profile.
The retained 53 episodes include failed demonstrations. Completion verifies
the reconstruction checks, not policy success or VGGT effectiveness.

The corrected 100-frame probe took 4.43 seconds after initialization, with
19.7 MB peak PyTorch allocation. Its maximum anchor discrepancy was 1.69 µm,
object mesh discrepancy 49.4 nm and velocity/Jacobian discrepancy 4.44e−16.
Full reconstruction is approximately 7–8 minutes using two GPUs sequentially
within each episode. Earlier probes without the COM-to-origin correction are
superseded and must not be used for training.

The completed 20,212-frame reconstruction took 421.5 seconds in parallel.
Across every frame, the maximum anchor discrepancy was 1.763 µm, object mesh
discrepancy 68.34 nm and velocity/Jacobian discrepancy 8.88e−16. All output
arrays were finite and their state/episode/frame rows exactly matched the
source. See `native_tactile_repair_result.json` for checksums and measured
output distributions.

## Physical-cadence data version

The initial version above used recorded wall timestamp differences for its
velocity proxy. Subsequent adjacent-state replay checks established that each
recorded state transition advances one `.01`-second physics step, despite the
approximately 20 Hz recording clock. See `physics_transition_audit.json`.

For the new data version, add `--velocity-dt .01` to probe and shard commands
and use the separate output directory `artifacts/native_physics_dt01`.
Reports record the fixed physical interval and retain each original wall
timestamp difference as `wall_dt_s`. This changes the velocity supplied to the
same native force law; it does not modify the inherited force law or its units.
The new version also requires the independently audited raw action labels;
`repair_action_labels.py` performs that operation separately from sensor
reconstruction. Existing v1 readouts and caches remain unchanged.
